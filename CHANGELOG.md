# Changelog

Any change to a tool schema on the server bumps the plugin version, gets a note here for the OpenAI re-review, and is batched into a Cursor release.

## 0.3.0

- Registry `server.json` 1.0.5: the MCP server no longer has the video commission tools (`video_commission`, `query_video_commissions`). The default profile is now 15 tools. Renders with `render_video` (campaign, template, still and Squid design video) are unchanged, and so are campaign images. This release publishes 1.0.5 to the registry first; the hosted server moves to 1.0.5 right after, because its version check waits for this `server.json` on main.
- The plugin drops video commissions to match: the `video` skill, the orientation skill and its tool reference (15 tools) and glossary, `adapt`, the read-only agents' `disallowedTools`, the smoke eval runner, the spend guard and its PreToolUse matcher, the job watch and its PostToolUse matcher, `scripts/test-hooks.sh`, README, and AGENTS.md.
- One server for everyone. Every install, Anthropic's plugin directory included, connects to `https://app.sparkletree.io/api/mcp`; there is no separate directory server.
- The `directory` branch is no longer generated. The `directory-branch` CI job, `scripts/ci-directory-branch.sh`, `scripts/directory-transform.sh` and `scripts/test-directory-transform.sh` are gone, and `scripts/ci-validate.sh` and `scripts/ci-check-bump.sh` no longer special-case it. The existing remote branch is left as it is. Anthropic's listing uses `main`. Tagging and the registry publish are unchanged.
- Listings describe SparkleTree as brand, web presence and campaigns online and on screens, not only campaigns: `plugin.json`, the Codex and Gemini manifests, `marketplace.json`, `server.json` and the OpenAI bundle.
- Directory validation: `.claude-plugin/icon.png` (512 px square PNG), `privacyPolicyUrl` in `plugin.json`, and the spend guard writes its two decisions (`ask`, `deny`) as literals, so a reader can see it never answers `allow`. Its behaviour is unchanged.

## 0.2.2

- Registry `server.json` 1.0.4: `query_analytics` `snapshot` gains the `siteActivity` section (the dashboard's Site activity panel: event kinds with key, label, source, site, count, sessions, properties and zeroResultCount; brand page views by path and by traffic source) and the `siteActivityBreakdown: {kind, property, limit?}` input for one property's values. Whole UTC days, up to 366 days back; unavailable with `campaignIds`, `productIds`, `storeIds` or `eventTypes`. Monorepo !1464, which sets `MCP_SERVER_VERSION` 1.0.4; merge this first, then rerun its `mcp-version-sync` job.
- Site activity. Skills now say how a site the agent builds gets into Dashboard > Analytics > Site activity. New `surfaces-and-embed/references/site-activity.md`: what is recorded without code (brand page views per path; impressions and clicks on campaign creative), and how to send the site's own actions with the SDK's `track` (`SparkleTree.track` from `/api/embed/v1/sdk/core.js` on a brand page, `track` from `@sparkletree/core` elsewhere): a campaign id of the workspace, `"click"` or `"custom"`, every detail inside `context`, `context.kind` as the event's name, the naming rules for breakdowns, a `results` number for searches that found nothing, and no personal data.
- `brand` asks which visitor actions the user wants to see and records them on the page as the agent guide's "Measure what visitors do" section shows (monorepo: same release as this note). `surfaces-and-embed`, its React reference, `analytics` and the tool reference point at Site activity and read it back with `query_analytics` `siteActivity`.

## 0.2.1

- Follows the final registry 1.0.3 server surface; `server.json` stays at 1.0.3. `check_component` and `match_templates` are now `manage_campaigns` actions, so `query_campaigns` carries only pure reads (`list_templates`, `get_template`, `get_component`, `forecast` and the rest). Their inputs, outputs, roles and limits are unchanged, and both still change no campaign data. Sending either to `query_campaigns` returns `invalid_input` naming `manage_campaigns`.
- Skills (`sparkletree`, its tool reference, `squid-design`), README "What the plugin runs" and "Who pays for what", SETUP, AGENTS.md and the `squid-design` and `squid-templates` eval graders name the new home.
- Hooks: the spend guard asks before `manage_campaigns` `check_component` and `match_templates` (daily allowance), and denies them inside the read-only `campaign-reviewer` and `analytics-digest` agents, which already list `manage_campaigns` in `disallowedTools`. `query_campaigns` is no longer in the PreToolUse matcher; a `query_*` call that reaches the script anyway passes silently. `scripts/test-hooks.sh` checks that the matcher names every guarded tool and no `query_*` tool.
- Spend guard fails closed (Codex review). It reads calls with jq only. The sed and awk fallback read decisions out of the JSON by text search, so an escaped action name (`del\u0065te`), a nested `"tool_name":"query_campaigns"` or a nested `"action":"draft"` before the real `delete` passed silently, and a nested tool name also slipped past the read-only agents. Now, without jq or when a call is not a JSON object with a string `tool_name` and an object `tool_input`, every call that reaches the guard asks in prompting modes, is refused once in auto, bypassPermissions and dontAsk modes (or when the mode cannot be read), and is denied inside `campaign-reviewer` and `analytics-digest`; the reason names the problem. The tool name comes from the top-level `tool_name` only.
- Spend guard approvals: the refuse-once marker is named by a SHA-256 digest (`shasum`, `sha256sum` or `openssl`) of the session id, the full tool name and `jq -cS` of the whole input. Before, the fallback keyed it by action and mode only and neither path included the connector, so a yes for one generation let a different one through, and identical input on another connector shared the yes. The marker is consumed with `mv`, so of several identical calls racing for one yes only one goes through, and a yes counts from 2 seconds to 15 minutes after the refusal. Without a SHA-256 tool the refuse-once step refuses every time.
- `scripts/test-hooks.sh` runs with jq, with `SPARKLETREE_NO_JQ=1` and with jq hidden from PATH (fallback cases now expect the fail-closed answers), plus the three bypass inputs, approval keying, a race of six identical retries, an expired yes and a run without a SHA-256 tool. A failed JSON check of the session hook output now fails the script; it used to be lost in a pipeline subshell. The `validate` CI job runs it.
- The generated `directory` branch also points `gemini-extension.json` at `https://app.sparkletree.io/api/mcp/directory`; before, Gemini CLI still connected to the full server there. The transform's check now scans every file in the tree for the full server URL, with documented exceptions (`server.json`, `CHANGELOG.md`, the transform and its test, and `scripts/build-openai-bundle.sh`). `scripts/ci-validate.sh` checks that `gemini-extension.json` and `.mcp.json` name the same server.
- `scripts/ci-check-bump.sh` counts changes to `.claude-plugin/`, `.codex-plugin/plugin.json` and `gemini-extension.json` as needing a plugin bump, except a change that only moves a manifest's version. New `scripts/test-ci-check-bump.sh`, run in CI.
- The tool reference no longer says `mosaic://capabilities` lists `ai_studio_image_workflow`: with registry 1.0.3 its prompt list names exactly the prompts the connection's profile serves.
- README "What the plugin runs, sends and fetches", SETUP, AGENTS.md and the `sparkletree` skill describe the fail-closed guard, the marker digest, and that the session start hook and job watch never use jq.

## 0.2.0

- CI: every push to `main` rebuilds the `directory` branch for Anthropic's directory. It is `main` with `.mcp.json` on `https://app.sparkletree.io/api/mcp/directory` (15 tools, no AI images, no AI video commissions) and those tools removed from the skills, agents, hooks, README and evals (`scripts/directory-transform.sh`, `scripts/ci-directory-branch.sh`). Tags and the `directory` branch are pushed with the CI job token; `GITLAB_TAG_TOKEN` is gone.
- Registry `server.json` 1.0.3: the live server gained, after registry 1.0.2, `upload_asset` and `query_assets`; `manage_brand` `set_logo`; variant media by `assetId`; the product image gallery actions; custom Squid designs (`query_campaigns` `get_component`, `manage_campaigns` `create_component`, `publish_component`, `revert_component`) and `render_video` `mode: squid`; `query_campaigns` `forecast`, `check_component`, `list_templates`, `match_templates`, `get_template` and `manage_campaigns` `apply_template`; `query_brand` `get_site` and `check_page`, and `manage_brand` `edit_page`, `create_version`, `put_files`, `create_file_upload`, `delete_files`, `delete_page` and `render_check`; `query_analytics` `creatives`, `creativesLimit` and export `includeCreatives`. `manage_brand` is now annotated destructive and not idempotent.
- Skills follow the live server (registry 1.0.3), 17 tools on the default profile, verified against the server source on 2026-10-15. New `products` skill: add, import and edit products; `upload_asset` for files without a public link (`from_url`, `from_data`, and `create_upload` then `complete_upload` for a local or large file, video up to 128 MB); `query_assets` to find files already stored; the product image gallery (`add_image`, `remove_image`, `set_primary_image`, `reorder_images`); the `PRODUCT_EXISTS` answer and `allowDuplicate`; clearing a price with `price: null`; CSV rows whose image cannot be stored are written without it, with a warning. New `squid-design` skill: custom Squid designs (`query_campaigns` `get_component`, `manage_campaigns` `create_component`, `publish_component`, `revert_component`, `contentStructure.squidSlots`, the `mosaic://campaigns/{id}/squid-component-guide` resource) and `render_video` `mode: squid` with `query_video` `progress` by campaign and variant. The manifest example now uses the `{source, name}` slot shape the server requires.
- Squid templates and design checks (`squid-design`): `match_templates` (member, may make a model call, 30 uncached matches per workspace per day), `list_templates`, `get_template` with a brand-baked starter, and `apply_template` as a draft (member) or with `publish: true` (admin), with `emptyClaimSlots` filled from real facts only. The library is off on some deployments; every template action then answers `not_configured` and the skill says templates are not available yet instead of retrying. `check_component` runs the static checks at once and, where browser checks are switched on, a browser check at five sizes in a sandbox (20 per workspace per day); every finding is a warning. `query_campaigns` `forecast` is listed in the tool reference.
- Brand pages and sites (`brand`): read a version with `get_page` `pageId`, `path` and `lines`; fix it with `edit_page` (exact-text edits, `expectedSha256`) instead of resending the page; check it with `check_page`; `render_check` in a sandbox (20 per workspace per day); `delete_page`; and multi-page sites with `create_version`, `get_site`, `put_files`, `create_file_upload` and `delete_files`. Members draft and check, admins publish, revert and delete. `adapt` edits an existing brand page with `edit_page`.
- Analytics (`analytics`, `analytics-digest`): headline impressions, clicks and conversions include Meta Ads at day granularity and up, with the SparkleTree and Meta split; Reach stays SparkleTree sessions and Meta reach is reported on its own; the `creatives` section and export `includeCreatives`; spend in each ad account's own currency. The digest agent no longer calls Impressions raw deliveries.
- Costs: `generate_campaign` sets aside the credits for its AI images when the call is accepted, in both modes, and answers `precondition_failed` with the numbers and a remedy (generate without images, retry later, ask the admin) when they are short. `render_video` `mode: squid` is recorded in a sandbox, not with render credits; a Starter workspace or one without an active plan gets `forbidden`, and a failed plan lookup `upstream_error`.
- The `brand` skill sets logos with `manage_brand` `set_logo` (`logoSlot`, `logoAssetId` or `logoUrl`) and names the plan rules for brand writes. Variant image and video take `{assetId}` or `{url}`.
- Wording: the launch flow now says "campaign plan" (what SparkleTree writes from the goal) and film commissions say "description"; `launch-campaign/references/brief.md` is now `references/plan.md`. The server identifiers `campaign_brief` and `briefMd` are unchanged. The orientation skill and README describe SparkleTree with the canonical wording.
- Renamed so a name alone says what the skill does, since Claude Code drops skill descriptions when the listing runs out of budget: `brand-voice-sync` is now `brand`, `video-from-winner` is now `video`, and the `digest` command is now the `analytics` skill.
- `analytics`, `status` and `adapt` can now be loaded by the model, not only typed as commands, so "how did my campaigns do", "what is live" and "every morning at 7, change the headline" reach them. `launch` and `setup` stay user-only.
- Every description rewritten with the main use case first and the user's likely words as triggers. The orientation skill carries a table that routes each kind of request to the right skill, says exactly which calls the hook guards, which drafts need no extra yes, and no longer calls every read-only tool free.
- Fixes: `manage_surfaces` `create_surface` takes `surfaceType`, not `type`, and surfaces and zones need the editor role, not member; brand writes cannot be made with an API key (it counts as a member), but a brand-page draft can; `generate_playbook` runs paid inference and is not free; activation can come back with `approval: {status: "required"}`; the tool table lists the actions added since 0.1.3, render caps and analytics window limits; the resource list names `ui://mosaic/campaign-inspector@2`, and the prompt list says `ai_studio_image_workflow` is not served on the default profile.
- Hooks. The spend guard now also covers `manage_products` `import_from_url` and `delete`, `manage_campaigns` `generate_playbook`, `update_deployment`, `update` to active, `duplicate`, `create_share_link`, `revoke_share_link`, `publish_component`, `revert_component`, and `create_component` and `apply_template` with `publish: true`, `manage_brand` brand data writes including `set_logo`, `publish_page`, `revert_page`, `delete_page`, `delete_files`, `render_check`, and `create_page` and `edit_page` with `publish: true`, `manage_surfaces`, `render_video` `mode: squid`, and `query_campaigns` `check_component` and `match_templates` (every other `query_campaigns` action passes silently). `update_variant` still passes, because the hook cannot see whether a campaign is live; the skills confirm it in chat. In auto, bypassPermissions and dontAsk modes, where an `ask` decision never reaches the user, a credit-spending call is stopped once with a reason that tells the model to confirm in chat; the same call made again within 15 minutes goes through (`SPARKLETREE_SPEND_GUARD=prompt-only` or `off` changes this). Inside the `campaign-reviewer` and `analytics-digest` agents every guarded call is denied, including the tools of a claude.ai connector, which `disallowedTools` cannot name. A new PostToolUse hook (`job-watch.sh`) records paid starts, so a second start in the same session is flagged in the prompt. The SessionStart hook adds one routing line to the context (opt out with `SPARKLETREE_SESSION_CONTEXT=off`). Hook commands now quote `${CLAUDE_PLUGIN_ROOT}`; `claude plugin validate --strict .claude-plugin/plugin.json` failed on the unquoted form.
- README: rewritten as the directory listing. It says what the plugin does first, lists every part including the three hooks, and has a section that discloses everything the plugin runs, sends and fetches (the health check, the routing line, the spend guard's decisions and marker files, the job-watch markers, no other network calls). "Who pays for what" is current. SETUP names the environment switches.
- Evals: new cases for `products`, `squid-design`, `analytics`, `status` and `adapt`, plus `squid-templates` and `brand-page`. Prompts now forbid SparkleTree tools but allow loading skills; the old wording forbade every tool, which made the `tool_used` grader fail even when the model chose the right skill. New `scripts/test-hooks.sh` (jq and sed paths, and a check that the PreToolUse matcher names every guarded tool); CI runs it and validates `.claude-plugin/plugin.json`.

## 0.1.0 (unreleased)

First version of the plugin.

- Manifest, one-plugin marketplace, MCP server declaration for `https://app.sparkletree.io/api/mcp`.
- Eight model-invocable skills (`sparkletree`, `launch-campaign`, `review-variants`, `brand-voice-sync`, `surfaces-and-embed`, `video-from-winner`, `agency-workspaces`, `troubleshoot-connection`) and four user-invoked commands (`setup`, `launch`, `digest`, `status`).
- Two read-only agents: `campaign-reviewer`, `analytics-digest`.
- Session-start health check and a pre-tool spend guard, both POSIX sh without dependencies. The guard matches the four spend and destructive tools under any MCP server name, because Claude Code drops the plugin's server when a claude.ai connector for the same URL is present and the tools then carry the connector's id.
- Eval cases for every model-invocable skill, plus a `claude -p` fallback runner.
- `server.json` for the official MCP registry (`io.sparkletree/sparkletree`), `gemini-extension.json`, and an OpenAI skills-only bundle generated from the same skills.

Tool surface: the skills target the 15-tool default that the pending server release introduces, where the read actions of `manage_brand`, `manage_surfaces` and `video_commission` move to `query_brand`, `query_surfaces` and `query_video_commissions`. On a server that still exposes the 12-tool surface, use `manage_brand action=get`, `manage_surfaces operation=list_surfaces|get_surface|list_zones` and `video_commission action=list|get` for those reads; everything else is unchanged.
